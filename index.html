    💾 Situação do backup

    O plano gratuito do Firebase não faz backup automático — quem protege é a rotina
    Backup: verificando… —

    1 · Dados (JSON)

    o backup de dados de verdade

    Leva todas as seções: equipamentos, técnicos, setores, empréstimos, guias (com as assinaturas), impressoras, switches, racks, licenças, listas, wiki e tipos/marcas.

    Restaurar troca os dados da tela e sincroniza com a nuvem — confirma antes, e a nuvem recebe por fusão (nada é apagado por completo; ideal com a nuvem vazia). Guarde o arquivo baixado fora deste computador.

    2 · Arquivos (ZIP)

    prints e documentos da Wiki

    Baixa todos os prints e documentos anexados — os binários que o JSON nunca alcança. Limite de 1.000 arquivos ou 64 MB por ZIP.

    O ZIP é a cópia de segurança offline: não há importação em massa — para os arquivos voltarem ao sistema, são reenviados pelo painel 📁 da Wiki.

    3 · Código do sistema

    fora do navegador

    O código não é baixado por aqui: ele fica na pasta do projeto (bkp-codigo-AAAAMMDD.zip — fonte, index publicado, Worker, regras, checklist e gerador) e inteiro no GitHub mauricioliberato/Patrimonios-SEDEF.

    🗄️ Onde os dados ficam

    referência
    • Dados/texto → Firebase Firestore (projeto patrimonio-395c5), coleção sistema/ — uma "página" por seção.
    • Prints e documentos → Cloudflare Workers KV wiki-imagens (1 GB grátis; anexos até 8 MB).
    • Guias e comprovantes → registros no Firestore com as assinaturas dentro deles; o PDF não é salvo — é montado na hora (imprima em PDF para guardar a cópia visual).
    • Usuários → Firebase Auth · Código → GitHub + Cloudflare Workers.

    🗓️ Rotina recomendada

    semanal, ou depois de qualquer mudança grande
    1. ⬇ Exportar backup (JSON) — item 1 acima.
    2. ⬇ Tudo (ZIP) — item 2 acima.
    3. Guardar os dois arquivos fora deste computador (pendrive/nuvem pessoal).
    A barra lateral mostra ✓ Backup (verde) até 7 dias da última exportação e ⚠ (laranja) depois — inclusive nesta tela, no cartão de situação.

    📖 Guia de backup e restauração

    passo a passo para criar, guardar e restaurar — clique nos títulos para abrir
    🅰️ Criar o backup (passo a passo)
    1. Entre no sistema (precisa estar logado) e abra o menu 💾 Backup e Restauração.
    2. Dados (JSON): clique em ⬇ Exportar backup (JSON). O navegador baixa o arquivo nii-patrimonios-backup-AAAAMMDD.json com todas as seções: equipamentos, técnicos, setores, empréstimos, guias (com as assinaturas), impressoras, switches, racks, licenças, listas, wiki e tipos/marcas.
    3. Arquivos (ZIP): clique em ⬇ Tudo (ZIP). Baixa o backup-wiki-AAAAMMDD.zip com todos os prints e documentos anexados (limite de 1.000 arquivos ou 64 MB — se avisar que é grande demais, baixe pelo painel 📁 Arquivos, em partes).
    4. Guarde os dois arquivos FORA deste computador — pendrive, HD externo ou nuvem pessoal. Pasta do PC não é backup.
    5. Frequência: semanal, e sempre depois de mudanças grandes (cadastro em massa, exclusões, restaurações). O indicador da barra lateral fica ✓ verde até 7 dias da última exportação e ⚠ laranja depois.
    🅱️ Restaurar o backup

    Quando usar: PC novo ou disco trocado, dado apagado por engano, nuvem zerada, troca da conta do Firebase.

    1. Abra 💾 Backup e Restauração.
    2. Clique em ⬆ Restaurar de um backup e escolha o arquivo JSON (prefira o mais recente).
    3. Leia o aviso na tela e confirme.
    4. A tela assume os dados do arquivo e o sistema sincroniza com a nuvem — depois, dê F5 nas abas abertas para todo mundo receber.

    Atenção — fusão: a nuvem recebe os itens por fusão (nada é apagado por completo). É ideal quando a nuvem está vazia/zerada; se ela estiver cheia de dados diferentes, os dois conjuntos podem coexistir.

    Guias: a numeração continua da maior guia restaurada + 1.

    Arquivos (ZIP): não têm importação em massa — para prints e documentos voltarem ao sistema, são reenviados pelo painel 📁 Arquivos.

    🅲 O que NÃO entra no JSON
    • Prints e documentos da Wiki → use o ⬇ Tudo (ZIP).
    • Código do sistema → pasta do projeto (bkp-codigo-*.zip) e GitHub.
    • PDFs impressos → o sistema não guarda a folha pronta (ela é remontada na hora a partir do registro); ao imprimir, escolha “Salvar em PDF” se quiser a cópia visual.
    🅓 Dicas de segurança
    • Antes de restaurar, exporte um backup do estado atual — assim você não perde o que estava na tela.
    • Guarde no mínimo os 2 últimos JSONs (os nomes já trazem a data).
    • Se o indicador mostrar “nunca exportado”, faça o primeiro backup agora.
    • Restaurar troca os dados da tela e sincroniza para todo mundo — combine antes com a equipe, se mais gente estiver usando.
